# Deep Dive：推荐系统（多路召回）

## 1. 架构分层

```text
曝光点击 → Kafka → 行为存储
                ↓
        离线 Job（ItemCF 等）→ Redis 列表
在线：请求 → 多路召回(并行) → 融合/打散 → 填充 → 返回
失败 → 热门兜底
```

## 2. 召回通路

| 通路 | 信号 | 备注 |
|------|------|------|
| Hot | 销量/热度 | 冷启动 |
| CategoryHot | 类目偏好 | 简单统计 |
| ItemCF | 共现相似 | 可解释 |
| Vector | Milvus | 语义相似 |

每路实现统一接口：`List<RecallItem> recall(UserCtx ctx, int n)`。

## 3. ItemCF 要点

- 共现矩阵：同用户正向行为物品对  
- 相似度：余弦/Jaccard（选定写清）  
- 给用户推荐：取其历史物品的相似物加权求和  
- 过滤已购、下架、黑名单  

## 4. 在线预算

- 总超时例如 80ms  
- 向量路 40ms 超时取消  
- 融合只使用已返回路  

## 5. 评估

- 离线：HitRate/NDCG（有标注才做）  
- 在线：CTR、加购率、停留（埋点）  
- 对比：开/关向量路的差异（简单 A/B 开关）
