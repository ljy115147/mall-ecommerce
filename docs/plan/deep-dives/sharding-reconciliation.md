# Deep Dive：分库分表与三方对账

## 1. 分片键选择

订单表常见：

- 按 `user_id`：用户维查询友好；运营按订单号查需解析路由  
- 按 `order_id`：需订单号生成时嵌入分片位  

**建议**：订单号 = 时间因子 + 分片位 + 序列；分片位来自 userId hash。

## 2. ShardingSphere 关注点

- 绑定表：`order` 与 `order_item`  
- 分布式主键  
- 避免同时改多分片的事务  
- 分页：`limit` 深翻页代价  
- 禁止无分片键的全路由（或严格管控）  

## 3. 迁移策略

1. 新库分片结构  
2. 双写或停写窗口拷贝  
3. 校验行数/金额校验和  
4. 切读  
5. 观察期后停旧库  

面试讲清：**校验和** 与 **回滚开关**。

## 4. 三方对账

```text
渠道账单 ──┐
支付单   ──┼─→ 差异单 → 人工/自动调账
订单应收 ──┘
库存流水 vs 订单占用/销售（业务对账）
```

差异类型：渠道多、我方多、金额不一致、状态不一致、延迟。

## 5. 资金安全叙事

- 支付单与订单状态机分离  
- 所有资金变更留流水  
- 对账日清；差异有主责与时效
