# 非功能需求（NFR）

## 1. 性能

| 场景 | 要求（自测填写实数） |
|------|----------------------|
| 商品详情读 | 多级缓存命中时 P99 低延迟；穿透可接受有界 |
| 普通下单 | 记录基线；优化后对比 |
| 秒杀扣减 | 超卖=0；尽量将写放大转移到 Redis+Kafka |
| 搜索 | 混合检索 P99 可接受；向量超时（如 150–300ms）则降级 |
| RAG | 首 token/全文超时阈值；超时返回检索结果或抱歉话术 |

压测资产目录建议：`deploy/perf/`（脚本+报告）。

## 2. 可用性与降级

必须可配开关（配置中心或动态配置表）：

| 开关 | 降级行为 |
|------|----------|
| `rec.enabled=false` | 首页推荐改热门 |
| `vector.search=false` | 仅 ES |
| `ai.rag=false` | 客服转「常见问题列表」 |
| `seckill.enabled=false` | 活动页维护公告 |
| `behavior.collect=false` | 停止埋点写入（保主链路） |

原则：**交易链路不依赖推荐/AI/语义检索的同步成功**。

## 3. 一致性

| 场景 | 策略 |
|------|------|
| 下单与库存占用 | 本地事务 |
| 订单事件下游 | Outbox + Kafka 最终一致 |
| 秒杀 Redis 与 DB | 异步落库 + 对账 |
| ES/Milvus 与 DB | Canal/事件最终一致 + 全量重建 |
| 支付与订单 | 回调幂等 + 对账 |

## 4. 安全

- OWASP 基础：注入、XSS、CSRF（若 Cookie 方案）、越权
- 商家隔离自动化测试
- 密钥轮转流程文档化
- 支付回调验签必测
- LLM：最小权限知识库；输出过滤；审计日志

## 5. 可观测性

**黄金指标**：

- RED：Rate、Errors、Duration（按接口）
- 业务：下单成功率、支付成功率、关单数、秒杀成功率、超卖检测计数、对账差异数、搜索零结果率、推荐 CTR、RAG 无引用回答率
- 消息：生产失败、消费失败、Lag、DLQ 增长速度

日志：JSON；必带 `traceId`、`userId`(可脱敏)、`orderId`。

## 6. 容量与扩展

- Kafka 分区随秒杀吞吐扩展
- 订单分片提前按 user_id/order_id 设计
- AI Embedding 可水平扩多副本
- Redis 内存评估：库存分桶、推荐列表、会话

## 7. 灾备（方案级）

2 年内要求：

- 每日 DB 备份 + 恢复演练（至少每季度 1 次）
- Kafka 与 Milvus 数据可重建（商品可重放 embedding；ES 可全量重建）
- 多活：输出设计文档即可，不强制双机房落地
