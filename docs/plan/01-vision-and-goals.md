# 愿景、目标与面试叙事

## 1. 一句话定位

自研一套 **平台型电商交易与增长中台**：支持多商户经营、大促秒杀与拼团、费用算价与资金对账、Kafka 事件驱动、ES+Milvus 混合检索、多路召回推荐与 RAG 智能客服，并从模块化单体演进到可独立扩缩容的微服务体系。

## 2. 对标业务（拼多多相关能力映射）

| 拼多多常见能力 | 本项目对应 | 面试可讲点 |
|----------------|------------|------------|
| 货找人 / 推荐 feed | 多路召回 + 向量召回 + 降级 | 召回/融合/冷启动 |
| 拼团裂变 | 团状态机 + 超时关团 + 退款 | 一致性与幂等 |
| 大促秒杀 | Redis 分桶 + Kafka 异步 + 风控 | 超卖、热点、限流 |
| 平台多店 | 商家/店铺/商品归属 | 越权与数据隔离 |
| 搜索 | ES 关键词 + Milvus 语义混合 | 双路召回与降级 |
| 客服/售后 | 售后状态机 + RAG 客服 | 幻觉治理、知识更新 |
| 资金安全 | 支付单/退款单/三方对账 | 账实一致 |

## 3. 成功标准（2 年末）

### 3.1 产品与工程

- [ ] C 端、平台运营端、商家端均可演示完整主路径
- [ ] 沙箱/模拟支付可走通；退款与售后闭环
- [ ] 拼团、秒杀、优惠券、推荐、语义搜索、RAG 客服均可现场演示
- [ ] Docker Compose 一键起基础设施；核心服务全部容器化  
- [ ] Kubernetes staging：Ingress + 探针 + 滚动发布/回滚可演示；CI 构建推送镜像
- [ ] 微服务拆分完成，推荐/AI 故障不影响下单（可演）
- [ ] 订单分库分表 + 支付三方对账跑通
- [ ] Grafana 大盘 + SkyWalking 链路 + Kafka Lag 监控齐全

### 3.2 量化基线（自行压测后填实数，以下为建议目标）

| 指标 | 建议目标 |
|------|----------|
| 秒杀接口（扣减路径） | 单机/小集群下可讲清瓶颈；**超卖 = 0** |
| 普通下单 P99 | 记录优化前后对比（有对比即可） |
| Kafka 秒杀消费 Lag | 压测峰值后可在约定时间消化 |
| 混合检索可用性 | 向量故障时自动降级，搜索可用率 ≈ 100% |
| 对账 | 日终差异可解释，差异单有处理流 |
| 推荐 | 有 CTR/加购率统计与一次降级演练 |

### 3.3 面试材料

- [ ] 1 页总架构 + 6 张以上核心时序图
- [ ] ≥ 10 个深挖故事（含故障复盘）
- [ ] 简历项目描述 4–6 条，每条能量化或点名技术决策
- [ ] 能从业务 → 模型 → 存储 → 消息 → 稳定性完整串讲 20 分钟不看稿

## 4. 面试叙事主线（建议背熟）

1. **为什么先单体**：先验证交易闭环与领域边界，避免分布式一上来拖死交付。  
2. **最难的业务**：秒杀超卖、拼团一致性、算价快照、资金对账。  
3. **为什么上 Kafka**：多消费者、行为流、峰值削峰、可重放；关单用 Job+事件而非伪延迟插件。  
4. **为什么上向量**：语义召回补齐关键词短板；与推荐/客服共用 Embedding 管道。  
5. **怎么演进微服务**：按已稳定边界拆，Outbox 最终一致，AI/推荐隔离。  
6. **我如何保证线上感**：压测、对账、降级、Lag、混沌与复盘。

## 5. 明确不做（防止无限膨胀到无法收尾）

即使有 2 年，下列内容 **不作为交付承诺**（可在演进章节口头提）：

- 真实多地多活生产容灾（可做「方案设计 + 单机房演练」）
- 完整自研大模型训练/RLHF
- 完整 WMS/全国仓配网络
- 直播带货、短视频内容中台
- 跨境/多货币/多时区清关

若时间充裕，优先加深：**交易一致性、秒杀、对账、检索推荐、Kafka 治理、稳定性**，而不是再开新业务线。

## 6. 角色假设（方便写文档口吻）

你同时扮演：架构师、交易后端、搜推工程、SRE。每个季度选一个「主角色」写复盘，面试时呈现深度而不是「什么都碰了一点」。
