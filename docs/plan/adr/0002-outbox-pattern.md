# ADR-0002：采用 Transactional Outbox

- 状态：Accepted
- 日期：2026-07-16

## 背景

订单/拼团等状态变更需通知下游，又不能「先发消息再提交事务」造成幽灵消息。

## 决策

业务库同事务写入 `outbox_event`，由 Relay 异步投递 Kafka；消费者幂等。

## 备选方案

1. 本地消息表（同 Outbox）。  
2. Kafka 事务消息 / EOS：复杂度高，收益有限。  
3. 先发 MQ 再写库：拒绝。  

## 后果

最终一致；Relay 需监控；至少一次投递。

## 验证方式

杀 Relay 再恢复，消息不丢；重复投递下游不双写。
