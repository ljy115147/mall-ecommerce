# ADR-0001：消息中间件选择 Kafka

- 状态：Accepted
- 日期：2026-07-16

## 背景

系统需要领域事件、秒杀削峰、行为流多消费者、检索/向量管道、对账重放能力。

## 决策

采用 **Apache Kafka（KRaft）** 作为唯一主消息中间件。

## 备选方案

1. RabbitMQ：路由灵活、延迟插件方便，但多消费者独立进度与重放、流式生态较弱。  
2. RocketMQ：国内电商常见，亦佳；本项目为对齐大数据/流式与可重放叙事选 Kafka。  

## 后果

- 正面：削峰、多订阅、重放、与 Canal/Flink/数仓集成顺滑。  
- 负面：无原生延迟队列；运维更重；学习曲线。  

## 验证方式

Outbox→Kafka→Consumer 示例；秒杀命令堆积可扩消费者消化；Lag 大盘。
