# P4 — 推荐多路召回 + RAG 客服 + 商家 AI（Month 12–14）

## 目标

形成「货找人」与 AI 应用闭环：行为数据 → 多路召回（含向量）→ 可运营可降级；RAG 客服可引用知识；商家文案辅助。

## Month 12 — 行为与 ItemCF

- [ ] 前端埋点：expose/click/cart/order（带 itemId、pos、scene、ts）
- [ ] 网关接收后发 Kafka（失败不影响页面）
- [ ] 行为落库；分区或按月表（提前考虑量）
- [ ] ItemCF 离线 Job（共现 → 相似度 → 用户推荐列表）
- [ ] Redis：`rec:home:{userId}`，TTL
- [ ] 未登录/冷启动：全站热门 + 类目热门
- [ ] 管理端 CTR 粗报表

**难点**：埋点重复；刷单行为污染；Job 耗时与增量更新。

## Month 13 — 向量召回与融合

- [ ] 用户近期点击商品向量平均/加权 → Milvus 搜相似
- [ ] 召回管道接口化：`RecallSource` 多实现
- [ ] 融合：加权 + 打散（类目多样性简单规则）
- [ ] 置顶/黑名单
- [ ] 推荐超时预算（如 50–80ms 本地融合，向量并行超时取消）
- [ ] 降级演练复盘

**难点**：多路延迟长尾；多样性与相关度权衡；评估指标定义。

## Month 14 — RAG 与商家 AI

### RAG 客服
- [ ] 知识文档管理；切片策略（长度/重叠）
- [ ] 写入 `kb_emb`；元数据：source、url、shopId?
- [ ] Chat API：session、messages、citations
- [ ] Prompt 模板：只依据资料回答；无依据则拒答
- [ ] 流式输出（可选 SSE）
- [ ] 敏感词与注入防护基础版
- [ ] 评测集：20 问，记录有无引用、是否胡编

### 商家 AI 辅助
- [ ] 输入类目+卖点 → 生成标题/卖点草稿
- [ ] 必须「应用」才写入商品；默认不自动上架
- [ ] 审计：生成内容与操作者

## 验收剧本

1. 新用户看热门；老用户看个性化  
2. 停推荐服务首页仍有商品  
3. 问「退货政策」返回答案+引用  
4. 问库外问题拒答  
5. 商家生成标题后手动保存  

## DoD

- 四路召回至少三路可用（热门/ItemCF/向量）  
- RAG 带 citations  
- 两篇故事：推荐降级、幻觉治理
