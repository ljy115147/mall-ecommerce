# P7 — 稳定性工程与混沌（Month 22）

## 目标

把「能跑」提升为「可运维、可演练、可讲 SLO」的线上感。

## 任务清单

### 全链路压测平台化
- [ ] 场景脚本：浏览 → 搜索 → 推荐 → 加购 → 下单 → 支付  
- [ ] 场景脚本：秒杀峰值  
- [ ] 场景脚本：拼团并发  
- [ ] 数据造数工具（用户、SKU、库存）  
- [ ] 报告模板自动化输出关键表  

### 混沌与预案
- [ ] 注入：杀 Pod、Kafka 消费暂停、Redis 增加延迟、DB 锁等待、AI 超时  
- [ ] 观察：降级是否生效、错误率、是否伤交易；K8s 事件与重启原因  
- [ ] （加码）Helm chart 或 GitOps 最小落地  
- [ ] 输出 runbook：`docs/runbooks/`（可新建）每故障一页；含「发布回滚」一篇  

### SLO
- [ ] 定义：下单可用性、支付成功率、搜索可用性、推荐降级成功率  
- [ ] 用 Prometheus 记录；Grafana 展示 Error Budget（简化版也可）  

### 安全回归
- [ ] 越权套件自动化  
- [ ] 依赖漏洞扫描（镜像/Maven/npm）  
- [ ] 密钥扫描进 CI  

## DoD

- ≥3 次混沌演练记录  
- runbook ≥5 篇  
- 全链路压测报告归档  
- 安全扫描无高危遗留（或有豁免说明）
