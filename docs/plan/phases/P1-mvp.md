# P1 — 多商户交易 MVP（Month 2–4）

## 目标

上线可演示的平台型电商最小闭环：**商家上架 → 买家下单 → 支付 → 发货 → 完成**，含超时关单与基础后台。

## Month 2 周任务 — 用户/商家/商品

### W1 用户与安全
- [ ] 注册/登录/刷新令牌策略（写清）
- [ ] 地址 CRUD；默认地址
- [ ] 密码哈希（BCrypt）；登录限流

### W2 商家与店铺
- [ ] 商家入驻表单；状态：待审/通过/拒绝（可手动改）
- [ ] 店铺；商家员工绑定（至少店主一人）
- [ ] 管理端审核页

### W3–W4 商品
- [ ] 类目树 API
- [ ] SPU/SKU 模型；价格分；条码可选
- [ ] MinIO 上传；图片引用
- [ ] 上下架；详情缓存
- [ ] 商家端商品 CRUD；平台端可强制下架
- [ ] 越权测试用例

## Month 3 周任务 — 购物车/订单/库存占用

### W1 购物车
- [ ] 加购/改数量/删/选中
- [ ] 失效 SKU 处理（下架）

### W2–W3 下单
- [ ] 结算页算价（P1 可先无券，只含商品金额）
- [ ] 创建订单 + 明细；收货地址快照
- [ ] 库存占用（事务内减 sellable、加 locked）
- [ ] 状态机 CREATED
- [ ] Outbox `OrderCreated`

### W4 取消与查询
- [ ] 用户取消 → 释放占用
- [ ] 订单列表分页；详情
- [ ] 管理端/商家端订单可见性过滤

## Month 4 周任务 — 支付/关单/上线

### W1–W2 支付域
- [ ] `payment` 表与状态机
- [ ] 模拟支付成功/失败接口（开关）
- [ ] 沙箱对接（微信或支付宝，至少一个）
- [ ] 回调验签 + 幂等（渠道流水号唯一索引）
- [ ] 成功后订单 → PAID；库存 locked→sold（或保持到发货再扣，**选定一种写 ADR**）

### W3 关单
- [ ] `pay_deadline` 字段
- [ ] XXL-JOB 每分钟扫描
- [ ] 发 Kafka `OrderClose`；消费者幂等关单
- [ ] 补偿：扫描 CREATED 且过期仍未关的订单

### W4 部署与演示
- [ ] 全应用多阶段 Dockerfile（backend/frontend/admin/ai）
- [ ] Compose 一键起「中间件 + 应用」；健康检查通过
- [ ] Nginx 反代；环境变量模板；镜像 tag（gitSha）
- [ ] CI 构建并推送至少 backend 镜像
- [ ] 种子数据脚本（类目、演示商家、演示商品）
- [ ] 演示录屏；面试故事「重复支付回调」
- [ ] Checklist MVP 验收全绿

## 关键验收剧本

1. 商家登录上架 2 个 SKU  
2. 买家加购下单  
3. 模拟支付成功 → 商家发货 → 买家确认  
4. 另一单不支付，等待关单 Job → 库存恢复  
5. 商家 B 无法看到商家 A 订单  

## 面试难点清单

- 地址/价格快照为何必要  
- 支付回调乱序、重复  
- 关单与支付成功并发（先支付后关单 / 先关单后回调）的互斥  
- 库存占用与售出的时点选择  

## DoD

- staging 可访问；核心剧本一遍通过  
- 有自动关单证据（日志/状态）  
- 支付幂等测试通过
