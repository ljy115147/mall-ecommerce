# P5 — 分库分表 / 读写分离 / 对账 / 数仓雏形（Month 15–17）

## 目标

数据面接近线上：订单可水平扩展、读可扩展、资金与库存可对账、分析有出口。这是与「玩具项目」拉开差距的阶段。

## Month 15 — 分库分表

- [ ] ADR：分片键（建议 `user_id` 或订单号反解析）
- [ ] 订单号生成器含分片信息
- [ ] ShardingSphere 规则：`order`、`order_item`、`order_fee_snapshot`、`order_state_log`
- [ ] 绑定表规则（order 与 item）
- [ ] 迁移方案：双写过渡或维护窗口；演练环境先跑
- [ ] 非分片键查询：禁止散炸；运营走 ES 订单宽表或离线库
- [ ] 全量回归交易/拼团/秒杀/售后

**难点**：分页、唯一索引、跨用户运营查询、分布式 ID 时钟。

## Month 16 — 读写分离与三方对账

### 读写分离
- [ ] 主从复制 Compose
- [ ] 路由：写主；读从；强制主库注解 `@Master`
- [ ] 清单：支付回调后查询、下单后立刻详情 → 走主

### 对账
- [ ] 渠道账单导入（文件/Mock API）
- [ ] 批任务：渠道 vs payment；payment vs order；stock_log vs order
- [ ] `recon_diff` 状态：OPEN/MATCHED/IGNORED/ADJUSTED
- [ ] 管理端差异处理；调整必须留审计
- [ ] 日终报告邮件或页面

**难点**：时间窗对齐、时区、部分退款、渠道延迟通知。

## Month 17 — Kafka 治理 + 数仓雏形 +（可选）Flink

- [ ] DLQ 管理：查看、重放、丢弃（需权限）
- [ ] Lag 分级告警与 runbook
- [ ] 同步订单/行为到 ClickHouse 或 Doris
- [ ] 基础分析 SQL：GMV、转化漏斗、秒杀转化
- [ ] （可选）Flink：滑动窗口热度 → Redis，供热门召回
- [ ] 容量文档：峰值估算、分区、消费者数

## 验收

- 分片环境完整下单支付退款  
- 人为制造支付差异能被对账扫出并处理  
- Lag 告警可演示  
- 分析库有日 GMV 查询  

## DoD

- ADR ≥ 3（分片、对账、读写）  
- 迁移演练记录  
- 面试故事：跨片查询踩坑
