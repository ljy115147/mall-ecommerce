# P2 — 大促峰值：库存中心 / 拼团 / 秒杀 / 风控（Month 5–8）

## 目标

具备大促级交易能力：库存可追溯、拼团正确、秒杀不超卖、有风控与压测复盘。这是简历 **含金量最高** 的阶段之一。

## Month 5 — 库存中心

### 任务
- [ ] 设计 `stock` / `stock_log`；迁移旧字段
- [ ] API：占用、释放、扣减、查询
- [ ] 所有下单改走库存中心
- [ ] 对账 Job：订单 LOCKED 数量 vs stock.locked
- [ ] 差异告警 + 管理端流水查询
- [ ] ADR：库存中心为何独立于商品目录

### 难点
- 流水幂等（biz_no）  
- 对账发现差异如何止血（禁止直接改可售而不留痕）

## Month 6 — 拼团

### 任务
- [ ] 团与成员模型；开团价校验
- [ ] 参团：库存/名额条件更新
- [ ] 成团仅一次：版本号或状态 CAS
- [ ] Kafka：成团成功 → 推进订单支付/履约策略（定义清楚：成团前是否预付）
- [ ] **建议已定**：参团时预支付或占座；失败自动退款（更接近真实，更难，含金量更高）
- [ ] 超时关团 Job
- [ ] C 端：开团、参团、团详情倒计时
- [ ] 并发测试：剩余 1 名时 100 并发参团

### 难点
- 成团临界；退款与库存顺序；消息重复导致二次成团

## Month 7 — 秒杀

### 任务
- [ ] 活动与 SKU 配置；开始/结束时间
- [ ] 预热：分桶 key `seckill:stock:{sku}:{bucket}`
- [ ] Lua/原子 DECR；失败返回售罄
- [ ] 用户限购（Redis Set/计数）
- [ ] 通过后写排队记录 + Outbox/直发 Kafka command
- [ ] 消费者创建订单；落 DB 库存流水
- [ ] 查询接口；超时报错可重试查询
- [ ] 读路径本地缓存活动信息

### 难点
- Redis 成功但 Kafka 失败的补偿  
- 分桶汇总与售罄判断  
- 热点店铺/商品缓存击穿  

## Month 8 — 风控与压测

### 任务
- [ ] Risk 模块：规则链（限频、黑名单、SKU 限购、设备指纹简化）
- [ ] 秒杀/领券入口强制 risk check
- [ ] 多层限流：Nginx/Gateway/应用
- [ ] 压测计划：目标并发、爬坡、持续、峰值
- [ ] 断言：超卖=0；重复下单=0；错误率阈值
- [ ] 故障注入清单执行并写复盘
- [ ] 大促演示日

### 压测报告必须包含
- 环境拓扑  
- 场景脚本  
- 结果表（QPS/P99/错误率/超卖检查 SQL）  
- 瓶颈与优化项  
- 残留风险  

## DoD

- 拼团并发用例通过  
- 秒杀压测超卖=0  
- ≥2 篇故障复盘  
- 风控可配置开关
