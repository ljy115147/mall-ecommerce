# 20 分钟项目介绍稿（结构）

## 0:00–1:00 开场

我做的是一个面向拼多多社招的平台型电商中台：多商户交易、大促秒杀与拼团、Kafka 事件驱动、ES+Milvus 混合检索、推荐与 RAG 客服，并从模块化单体演进到微服务。

## 1:00–4:00 业务与架构一图

- 画出：C 端/商家端 → Gateway → 领域服务 → MySQL/Redis/Kafka/ES/Milvus/AI  
- 强调：交易不依赖推荐/AI 同步成功  

## 4:00–9:00 最难三点（选与岗位匹配的）

**交易岗**：库存中心 + 秒杀不超卖 + 支付/关单竞态  
**消息岗**：Outbox + Kafka + Lag  
**搜推岗**：混合检索 + 多路召回 + 降级  
**平台岗**：分片 + 对账 + 微服务演进  

每点：问题 → 方案 → 数据。

## 9:00–14:00 一个完整故事深挖

例如「秒杀 Redis 成功但下游失败」或「拼团最后一名」——主动讲复盘。

## 14:00–18:00 演进与取舍

- 为什么先单体后拆  
- 为什么 Kafka、为什么 Job 关单  
- 为什么最终一致为主  

## 18:00–20:00 收尾

- 当前指标与演示环境  
- 已知不足与下一步（展示判断力）  
- 「您可以随便挑一块深挖」  

## 禁忌
